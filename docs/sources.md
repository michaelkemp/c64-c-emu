# External sources used

A running log of external documents/URLs actually fetched and read
during development, and what each one settled. Per this project's own
methodology (see `docs/references-and-gotchas.md`'s "read the primary
source text yourself" section), the goal is to always be able to trace
a specific implemented behavior back to a specific primary source
actually read — not "from memory" or a secondhand paraphrase. Add an
entry here whenever a new external source is fetched and used, in
roughly the phase order it was needed.

## Phase 1 — 6502 CPU core

- **Klaus Dormann's 6502 functional test suite** —
  https://github.com/Klaus2m5/6502_65C02_functional_tests (fetched via
  `scripts/fetch_dormann_tests.sh`, gitignored, never vendored). Its own
  `bin_files/6502_functional_test.lst` listing (generated by the suite's
  own author, part of the fetched copy) was read directly to confirm
  the documented success trap address (`$3469`) and the suite's load
  address/start label (`$0400`) — see `docs/6502-reference.md`.

## Phase 3 — CIA 6526

- **MOS 6526 CIA preliminary datasheet (Nov 1981)** —
  https://6502.org/documents/datasheets/mos/mos_6526_cia_preliminary_nov_1981.pdf
  Read in full (all 8 pages, via PDF image extraction — WebFetch's HTML/
  text conversion can't read this particular scanned PDF, so the actual
  page images were read directly instead of trusting a summary of them).
  Settled: the exact register map/offsets; CRA/CRB bit layouts (START,
  PBON, OUTMODE, RUNMODE, LOAD/force-load strobe, INMODE, SPMODE,
  TODIN) including Timer B's 2-bit INMODE (CNT pulses / Timer A
  underflow / Timer A underflow gated by CNT-high); the timer-latch vs.
  timer-counter distinction and the specific "writing the high byte
  while the timer is running updates the latch but does NOT reload the
  counter" nuance; ICR mask-write (bit 7 set/clear) and read-clears-all
  semantics; TOD's read-latching-on-Hours-until-Tenths-read behavior,
  the alarm/clock register aliasing via CRB bit 7, and that a write to
  the Hours register stops the clock while a write to Tenths restarts
  it; and the real RES-pin reset state (ports become inputs reading all
  high via passive pull-ups, timer control regs zero, timer *latches*
  reset to all-ones). See `docs/cia.md`.

- **Commodore 64 keyboard matrix layout** —
  http://sta.c64.org/cbm64kbdlay.html — fetched as raw text (not an AI
  summary of it — see this file's own note above) to get the exact
  8×8 key-position table and its exact hex bitmasks per column. This is
  the *specific* commonly-cited layout `docs/cia.md` refers to as one of
  (at least) two disagreeing community layouts — it has **not** been
  independently cross-checked against a real KERNAL/hardware empirical
  test (blocked on real staged ROMs, see `docs/memory-map.md`'s
  Phase 2 status), so treat the exact key-to-bit-position mapping as
  "sourced, but not yet empirically verified," per `docs/cia.md`'s own
  disclosed-gap convention. Corroborating (not independently fetched)
  search results agreeing on the PA=column-select/PB=row-sense
  direction: [c64os.com](https://c64os.com/post/howthekeyboardworks),
  [elite.bbcelite.com](https://elite.bbcelite.com/deep_dives/reading_the_commodore_64_keyboard_matrix.html),
  [c64-wiki.com](https://www.c64-wiki.com/wiki/Keyboard).
